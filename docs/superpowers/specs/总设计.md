## 1. 设计目标

在现有 CoastGPT (DINOv3 ViT-L16 + ConvNeXt Base + Llama-2-7B + MoE) 基础上，新增 FPN + 三头检测模块，实现：

- **检测头（精度路径）**：对已知类别输出 pixel 坐标，程序转换 WGS84 → GeoJSON
  - 养殖区：Instance Segmentation (RPN + bbox + mask)
  - 土地覆盖：Semantic Segmentation (per-pixel class → polygonize)
  - 海岸线：Edge Detection (heatmap → skeletonize → polyline)
- **LLM（泛化路径）**：保留 GeoJSON 文本生成能力，处理未知类别和灵活 prompt
- **推理融合**：known class 检测头优先 + unknown class LLM fallback (经校验)

### 检测头特征流约束（PoC-1 代码事实）

当前 PoC-1 代码中，`DualVisionEncoder.encode_with_spatial()` 返回 `(seq, g_grid, pyramid_raw)`：
- `seq`: DINO token 与 ConvNeXt token 经 heterogeneous fusion 后的 LLM 视觉序列
- `g_grid`: DINOv3 ViT spatial grid
- `pyramid_raw`: ConvNeXt `c4/c8/c16/c32` 多尺度特征

`Models/det_head.py::DualVisionFPNBackboneAdapter.forward()` 当前只解包 `pyramid_raw` 并送入 FPN：

```
image_seq, g_grid, pyramid_raw = self.vision.encode_with_spatial(images)
c4, c8, c16, c32 = pyramid_raw
p1, p2, p3, p4 = self.fpn(c4, c8, c16, c32)
```

因此，当前 Mask R-CNN / RPN 的直接检测特征来源是 **ConvNeXt local pyramid**，不是 DINO `g_grid` 或 fused `seq`。GF6 RPN recall 问题在未做额外接线或消融前，只能表述为“当前检测特征路径对 GF6 不够判别”，不能直接归因到 DINO ViT。若后续要解冻 DINO ViT，必须满足以下任一条件：
- 检测头显式接入 DINO `g_grid` 或 fused `seq`（例如 DINO-to-FPN adapter / fusion FPN）
- 消融实验证明 DINO 路径会影响检测头输入或检测性能
- 独立实现并验证 “DINO feature → detection head” 分支

## 3. 检测头详细设计 (三头架构)

### 3.1 FPN Neck

```
输入: ConvNeXt 4级特征
  c4  [B, 128, 56, 56]
  c8  [B, 256, 28, 28]
  c16 [B, 512, 14, 14]
  c32 [B, 1024, 7, 7]

处理:
  1×1 Conv 统一通道到 256
  top-down 上采样 + 横向连接

输出: P1-P4 [B, 256, Hi, Wi]
```

### 3.2 Aquaculture Instance Head — 养殖区

适用场景: 海水养殖区 (网箱/池塘)，每图可能多个实例，需要区分个体

```
结构:
  P2-P4 → RPN (3 scales × 3 ratios) → proposals
        → NMS top-K=100
        → RoIAlign 7×7 → FC → class (2: aquaculture + bg)
        → FC → bbox delta
        → RoIAlign 14×14 → 4×Conv → 28×28 mask

Loss:
  L_inst = L_rpn_cls + L_rpn_bbox + L_cls + L_bbox_l1 + L_giou + L_mask_bce

输出:
  [{class: "海水养殖区", score, bbox_xyxy, polygon_pixel}, ...]
```

### 3.3 Land-cover Semantic Head — 土地分类

适用场景: 32 类土地覆盖，语义分割任务（非 instance），无清晰个体边界

```
结构:
  FPN P1-P4 → 上采样 + concat → [B, 1024, 56, 56]
           → 3×3 Conv 256 + BN + ReLU
           → 3×3 Conv 128 + BN + ReLU
           → 1×1 Conv 33 → [B, 33, 56, 56] (32 land + background)
           → bilinear upsample → [B, 33, 224, 224]

后处理 (推理):
  bilinear upsample [B, 33, 56, 56] → [B, 33, 224, 224]  ← 统一到 model input pixel space
  argmax → class map [B, 224, 224]
  → connected components (per class)
  → contour extraction → polygon per component
  → filter small polygons (< min_area)

Loss:
  L_sem = CE (或 Focal) + Dice

类别:
  num_classes = 33 (32 land cover + background)
  不包含海水养殖区 (走 instance head)
  不包含海岸线 (走 edge head)
```

#### 为什么土地覆盖用 Semantic 而非 Instance Segmentation

土地覆盖任务的核心问题是"哪里是什么类型"，而非"第几个独立对象"。一张 tile 中同时出现多种土地覆盖类型，说明需要多类别像素级分类，但不等于必须实例分割：

```
多种类别共存 → 多类别语义分割 (semantic)
多个可独立编号/计数的对象 → 实例分割 (instance)
既要语义类别又要独立实例 ID → 全景分割 (panoptic)
```

Semantic Head 输出 per-pixel multi-class map [B, 33, 56, 56]，推理时按类别拆分 mask → connected components → contour extraction → polygonize，同样可以输出**多类别、多个 polygon**，甚至 MultiPolygon。

只有当任务要求对每个地块独立编号、计数或输出 instance_id 时，才需要 instance/panoptic segmentation。对本设计目标而言，semantic segmentation 完全胜任土地覆盖任务。

### 3.4 Coastline Edge Head — 海岸线

适用场景: 海岸线边界 (LineString)，连续线状特征

```
结构:
  FPN P1-P4 → 上采样到统一尺寸 (56×56)
           → Concat [B, 1024, 56, 56]
           → 3×3 Conv 256 + BN + ReLU
           → 3×3 Conv 128 + BN + ReLU
           → 1×1 Conv 1 → [B, 1, 56, 56]

后处理 (推理, 不参与训练):
  bilinear upsample [B, 1, 56, 56] → [B, 1, 224, 224]  ← 统一到 model input pixel space
  sigmoid → 阈值 0.5 → 二值化
  → skeletonize (形态学细化)
  → 最长连通路径 = 海岸线
  → Douglas-Peucker 简化 (epsilon=1.0px)
  → polyline 坐标 (224×224 model pixel space)

Loss:
  L_edge = BCE + Dice

类别:
  num_classes = 1 (coastline edge vs background)
```

## 5. LLM 参与方式

### 5.1 三种工作模式

| 前缀 | LLM 做什么 | 检测头 | 输出 |
|------|-----------|--------|------|
| [DET] | 任务识别 + 类别提取 + GeoJSON 泛化生成 | 执行检测 | 融合 GeoJSON |
| [CAP] | 自由生成自然语言描述 | 不使用 | 描述文本 |
| [VQA] | 自由生成问答 | 不使用 | 问答文本 |

### 5.2 Special Tokens 状态

当前 [DET]/[CAP] 不是 special tokens，被 tokenize 成 4-5 个字符 token。
MVP 阶段保持现状，后续优化时加入 tokenizer。
若决定加入 special tokens，应在 Stage 4 之前完成，避免训练中途修改 tokenizer。

### 5.3 推理融合策略 (known/unknown gating)

```
1. 解析 prompt → task type + target classes

2. [CAP]/[VQA] → 仅走 LLM，跳过检测头

3. [DET]:
   a) Known polygon classes → Aquaculture Instance Head + Land-cover Semantic Head
   b) Coastline → Coastline Edge Head
   c) Unknown classes → LLM fallback

4. 检测头结果:
   → 坐标转换 (pixel → source CRS → WGS84)
   → GeoJSON Builder 构造 features

5. LLM fallback 结果 (仅 unknown classes):
   → JSON parse 校验
   → GeoJSON schema 校验
   → 坐标范围校验 (tile bounds)
   → geometry validity 校验
   → class whitelist / unknown-class policy 校验
   → 面积/长度/点数异常过滤
   → 通过后才进入最终输出

6. 去重规则 (known vs unknown 重叠):
   - Polygon: projected CRS IoU > 0.5 → keep known
   - LineString: buffered IoU > 0.5 或 Chamfer distance → keep known
   - Point: distance < threshold → keep known

7. 输出: 最终 FeatureCollection
```

## 6. 数据管线

### 6.1 三条数据线

| 数据线 | 来源 | 样本数(估) | 分支 | 几何类型 | GT 获取方式 |
|--------|------|-----------|------|---------|------------|
| DET 养殖区 | Stage3Data/养殖区/GF1+GF2+GF6 | ~1,794 | instance head | Polygon | **Binary_WFQ.tif 优先** (connected components), GeoJSON fallback |
| DET 土地分类 | 土地分类/Patches | ~26,816 | semantic head | Polygon | **Label_Binary/*.tif 优先** (NEAREST resize → merge), GeoJSON 仅用于 georef/export |
| DET 海岸线 | 海岸线/RS-海岸线一级+二级 | ~4,787 | edge head | LineString | GeoJSON → WGS84→pixel → draw polyline |
| CAP 描述 | Stage2 + **新增** | ~92k + 2k-3k | LLM | 自然语言 | 文本标注 |
| VQA/其他 | Stage2 原有 | ~92k中部分 | LLM | 问答 | 文本标注 |

> **GT 策略变更 (2026-05-29, 修订 2026-06-02):**
> - **养殖区**: 数据自带 pixel-aligned binary mask (`Label_Binary/*_Binary_WFQ.tif`)，无需 WGS84→pixel 逆变换。GT 优先使用 binary mask (connected components → instance masks)，GeoJSON 仅保留用于 georef / WGS84 坐标闭环 / fallback。
> - **土地覆盖**: 数据同时有 `Label_GeoJSON/*.geojson` 和 `Label_Binary/*.tif`。**Binary TIF 是官方 ground truth**（在 tile 原生分辨率上 rasterize 后 resize 到 224×224），GeoJSON 不可直接 rasterize 到 224×224——因为 polygon bounds ≠ tile bounds，直接 rasterize 会导致 96% 像素不一致。GT 优先使用 Binary TIF (NEAREST resize → per-class merge)，GeoJSON 仅用于 georef / WGS84 坐标导出。

### 6.2 GT 标注获取

训练 GT 优先使用原始 binary mask（养殖区和土地覆盖均有此数据源），无 binary mask 时回退到 GeoJSON 逆变换。两条路径均经 round-trip 验证。

#### 6.2.1 Binary Mask GT (养殖区优先)

养殖区数据目录中 `Label_Binary/` 包含与原始图像像素对齐的 binary mask（`*_Binary_WFQ.tif`），黑色=background，白色=养殖区。此 mask 已处于 tile pixel space，无需任何 WGS84↔pixel 变换。

**GT 生成流程:**

```
Binary_WFQ.tif
  → Image.NEAREST resize 到 224×224 (禁止 bilinear)
  → cv2.connectedComponentsWithStats(connectivity=4)
  → 过滤 min_area < 8px 的小组件
  → instance_masks (list of [H,W] uint8)
  → boxes = bbox_from_mask
  → labels = 1 (海水养殖区)
```

**connectivity 选择:** connectivity=4 (仅上下左右相连)，避免斜角接触的独立养殖区块被错误合并。若标注语义要求斜角合并为同一实例，则切换 connectivity=8。

**GT consistency check (必须通过):**

```python
binary = Image.open(binary_path).convert("L")
binary = binary.resize((224, 224), Image.NEAREST)
binary_np = (np.array(binary) > 0).astype(np.uint8)

target_combined = target["masks"].sum(dim=0).clamp(0, 1).cpu().numpy()

iou = intersection / union  # >= 0.99 要求
area_diff_ratio = abs(binary_area - target_area) / binary_area  # <= 0.01 要求
```

**优势:**
- 已处于 tile pixel space，与原始图像天然对齐
- 不依赖 WGS84→pixel 反变换（消除 CRS、GSD、rasterize 规则误差）
- 不依赖 GeoJSON polygon 简化精度
- NEAREST resize 保持二值属性，不会产生灰度边缘

**GeoJSON 角色转换 (养殖区):**
- 不再是 mask 主来源
- 保留用于: georef 推导 (当 GeoTIFF 使用投影坐标系时)、WGS84 坐标闭环输出、无 binary mask 时的 fallback

#### 6.2.1b Binary TIF GT (土地覆盖优先)

土地覆盖数据中每个 class 目录下 `Label_Binary/` 包含 per-class 单通道 binary TIF（`*_Binary_CK.tif`），值为 0（background）或 255（foreground），在 tile 原生分辨率（128/256/512）上栅格化。数据同时有 `Label_GeoJSON/` 中的矢量标注。

**关键陷阱：polygon bounds ≠ tile bounds。** 直接对 GeoJSON 做 WGS84→224×224 rasterize 时，若以 polygon bounds 作为 affine transform 范围，等于把局部 polygon 放大到全图——实测产生 96% 像素不一致。Binary TIF 使用 tile 真实范围栅格化，不在 tile 范围内的区域保持 0，因此正确。

**GT 生成流程:**

```
Label_Binary/*.tif (per class, per tile)
  → Image.NEAREST resize 到 224×224 (禁止 bilinear)
  → 按 (source_image_key, grid, size) 分组，合并同 tile 不同 class 的 TIF
  → target[H,W] = IGNORE_INDEX(255)
  → for each class in merged tile:
       binary = (tif > 0)
       target[binary] = train_id  (1-24)
  → unlabeled 区域保持 255 (ignore in loss)
```

**分组 key:** `(source_image_key, grid, size)` — 同一卫星图像同 grid 同分辨率的 tile 共享 spatial extent，不同 class 目录下的 TIF 按此 key 合并为 multi-class target。26,816 merged tiles，multi-class 占 53%。

**优势:**
- TIF 使用 tile 真实 georeference 栅格化，与图像天然对齐
- NEAREST resize 保持二值属性，无灰度边缘
- 不依赖 WGS84→pixel 逆变换（消除 polygon bounds vs tile bounds 的 trap）
- 多类合并正确处理同 tile 中的 class overlap（last write wins）

**GeoJSON 角色转换 (土地覆盖):**
- 不再是 target mask 主来源

#### 6.2.2 GeoJSON 逆变换 GT (海岸线 / fallback)

不重新标注。利用现有 GeoJSON text answer + tile georef 逆变换:

```python
from affine import Affine
from pyproj import Transformer


def transform_ring_wgs84_to_model_pixel(ring, georef, transformer):
    """将单个 ring ([[lon,lat], ...]) 转换到 model pixel 坐标"""
    model_transform = Affine(*georef["model_transform"])
    inv_model = ~model_transform

    coords_crs = [transformer.transform(lon, lat) for lon, lat in ring]
    coords_pixel = [inv_model * (x, y) for x, y in coords_crs]
    return coords_pixel


def parse_polygon_to_pixel_rings(coordinates, georef, transformer):
    """Polygon: coordinates = [outer_ring, hole1, hole2, ...]"""
    return [
        transform_ring_wgs84_to_model_pixel(ring, georef, transformer)
        for ring in coordinates
    ]


def parse_multipolygon_to_pixel_polygons(coordinates, georef, transformer):
    """MultiPolygon: coordinates = [polygon1, polygon2, ...]"""
    return [
        parse_polygon_to_pixel_rings(poly, georef, transformer)
        for poly in coordinates
    ]


def parse_linestring_to_pixel(coordinates, georef, transformer):
    """LineString: coordinates = [[lon,lat], ...]"""
    return transform_ring_wgs84_to_model_pixel(coordinates, georef, transformer)


def parse_multilinestring_to_pixel(coordinates, georef, transformer):
    """MultiLineString: coordinates = [[[lon,lat],...], ...]"""
    return [
        transform_ring_wgs84_to_model_pixel(line, georef, transformer)
        for line in coordinates
    ]


def geojson_answer_to_pixel_gt(answer_text, georef):
    """
    answer_text: GeoJSON string (WGS84 coords)
    georef: {source_crs, original_size, model_input_size,
             original_transform, model_transform, resize_scale}

    Returns: pixel coords + bbox + mask GT
    """
    geojson = json.loads(answer_text)

    # Step 1: WGS84 → source CRS
    transformer = Transformer.from_crs(
        "EPSG:4326", georef["source_crs"], always_xy=True
    )

    for feature in geojson["features"]:
        geom_type = feature["geometry"]["type"]
        coords = feature["geometry"]["coordinates"]

        if geom_type == "Polygon":
            rings = parse_polygon_to_pixel_rings(
                coords, georef, transformer
            )
            outer_ring = rings[0]
            bbox = [
                min(col for col, row in outer_ring),
                min(row for col, row in outer_ring),
                max(col for col, row in outer_ring),
                max(row for col, row in outer_ring)
            ]
            mask = rasterize_polygon(outer_ring, holes=rings[1:], size=...)
            yield {"branch": "instance", "class": ..., "bbox": bbox, "mask": mask}

        elif geom_type == "MultiPolygon":
            polygons = parse_multipolygon_to_pixel_polygons(
                coords, georef, transformer
            )
            all_coords = [
                pt for poly in polygons for pt in poly[0]
            ]
            bbox = [
                min(col for col, row in all_coords),
                min(row for col, row in all_coords),
                max(col for col, row in all_coords),
                max(row for col, row in all_coords)
            ]
            mask = rasterize_polygon(
                [p[0] for p in polygons],
                holes=[h for p in polygons for h in p[1:]],
                size=...
            )
            yield {"branch": "semantic", "class": ..., "bbox": bbox, "mask": mask}

        elif geom_type == "LineString":
            line_pixel = parse_linestring_to_pixel(
                coords, georef, transformer
            )
            edge_map = draw_polyline(line_pixel, size=(224, 224), width=2)
            yield {"branch": "edge", "edge_map": edge_map}

        elif geom_type == "MultiLineString":
            lines_pixel = parse_multilinestring_to_pixel(
                coords, georef, transformer
            )
            edge_map = np.zeros((224, 224), dtype=np.float32)
            for line in lines_pixel:
                edge_map = np.maximum(
                    edge_map, draw_polyline(line, size=(224, 224), width=2)
                )
            yield {"branch": "edge", "edge_map": edge_map}
```

**Round-trip 单元测试（必须通过）:**

```
WGS84 → source CRS → original pixel → source CRS → WGS84
平均误差 < 1e-6 degree (或转换为米后 < 阈值)
```

### 6.4 Resize 同步 georef 处理

海岸线/养殖区数据 Size_256 → 224:

```python
from affine import Affine


def resize_georef(original_size, target_size, original_transform):
    """
    resize 后同步更新 affine transform。

    original_size: [width, height]
    target_size: [width, height]
    original_transform: GDAL-order affine [a, b, c, d, e, f]

    使用 orig_affine * Affine.scale(sx, sy) 写法，兼容 rotation/shear 场景。
    """
    sx = original_size[0] / target_size[0]
    sy = original_size[1] / target_size[1]

    orig_affine = Affine(*original_transform)

    # model_affine: model pixel → original pixel → geospatial
    # 等价于先缩放 model pixel 到 original pixel，再应用 original affine
    model_affine = orig_affine * Affine.scale(sx, sy)

    return list(model_affine)[:6], (sx, sy)
```

像素坐标约定:
- Polygon 顶点: pixel **corner** 坐标 (0-indexed)
- LineString 点: pixel **center** 坐标 (row+0.5, col+0.5)
- Mask rasterization: pixel grid (整像素)
- 不定义 0.5px 偏移则引入系统性米级误差

**统一 Model Pixel Space:**
- 所有检测头最终输出统一映射到 model input pixel space (224×224)
- Instance Head: bbox/mask 直接输出在 224×224 空间
- Semantic Head: logits upsample 到 224×224 后做 contour extraction
- Edge Head: logits upsample 到 224×224 后做 skeletonize
- 坐标转换模块统一使用 model_transform (224×224 ↔ source CRS)

### 7.5 Stage 3.5: Partial Unfreeze Detection Feature Path（按需引入）

```
目标: 解决当前检测特征路径对特定传感器纹理不够判别性的问题（如 GF6 RPN recall 低）

前置约束:
  - 先确认检测头实际消费的特征来源
  - 当前 PoC-1: detection head <- FPN <- ConvNeXt pyramid_raw(c4/c8/c16/c32)
  - 因此当前优先解冻 ConvNeXt local branch，而非 DINO ViT

触发条件:
  - GF6 RPN recall < 0.75 且 oversampling/expanded AR 均无效
  - 或 per-sensor RPN recall 差异 > 0.15

配置:
  优先解冻: ConvNeXt last 1-2 stages / blocks（与 FPN 输入一致）
  保持冻结: DINOv3 ViT, LLM base, Projector/LoRA（除非进入 Stage 4）
  ViT 解冻条件: 仅当检测头接入 DINO/fused features 或消融证明 DINO 路径影响检测
  训练: FPN + Detection Head (保持训练)
  lr_backbone: lr_head × 0.01 (e.g. 5e-7 vs 5e-5)
  epochs: 10-20 (防 overfit)
  监控: non-GF6 F1 不下降 > 0.02

风险:
  - 解冻 encoder 可能破坏预训练特征 → non-GF6 退化
  - 若未接入 DINO/fused features 却解冻 ViT，实验结论无效或难解释
  - NPU 显存增加，可能需减小 batch size
  - 需严格按源图像 split 评估，确认非过拟合
```

## 8. 坐标转换模块

### 8.1 训练时: WGS84 → Pixel (逆变换)

```python
from affine import Affine
from pyproj import Transformer

def wgs84_to_pixel(coords_wgs84, georef):
    """
    georef: {crs, model_transform (list of 6), resize_scale}
    Returns pixel corner coords for model input
    """
    transformer = Transformer.from_crs("EPSG:4326", georef["source_crs"], always_xy=True)
    coords_crs = [transformer.transform(lon, lat) for lon, lat in coords_wgs84]

    model_transform = Affine(*georef["model_transform"])
    inv_transform = ~model_transform
    coords_pixel = [inv_transform * (x, y) for x, y in coords_crs]

    return coords_pixel
```

### 8.2 推理时: Pixel → WGS84 (正向转换)

```python
def pixel_to_wgs84(coords_pixel, georef):
    """
    coords_pixel from detection head (model input space)
    """
    model_transform = Affine(*georef["model_transform"])
    coords_crs = [model_transform * (col, row) for col, row in coords_pixel]

    transformer = Transformer.from_crs(georef["source_crs"], "EPSG:4326", always_xy=True)
    coords_wgs84 = [transformer.transform(x, y) for x, y in coords_crs]

    return coords_wgs84
```

## 9. GeoJSON 校验管线 (P0)

程序构造可提高 JSON 语法合法率，但不能保证几何合法。

### 9.1 校验步骤

```
1. JSON parse: 能解析为合法 JSON
2. GeoJSON schema: type=FeatureCollection, features 数组
3. Per-feature schema: type=Feature, properties.class/confidence, geometry
4. Geometry validity (shapely):
   - Polygon: closed, non-self-intersecting, correct ring direction
   - LineString: >= 2 points, no duplicate consecutive points
   - MultiPolygon: no overlapping sub-polygons
5. Coordinate range: 是否在 tile bounds 内
6. Empty output: features=[] 正确处理
7. Sliver polygon / tiny geometry: 面积/长度过滤
```

### 9.2 校验失败处理

```
1. Polygon not closed → auto-close
2. Ring direction wrong → orient(ccw=True)
3. Self-intersection → buffer(0) repair
4. Tiny geometry → filter (min_area / min_length)
5. Invalid JSON → reject LLM output, fallback to det-only
```

### 14.2b PoC-2a: GF6 RPN Recall 修复 (进行中)

**问题:** GF6 传感器影像 RPN proposal recall 仅 0.695，导致 GF6 final recall 0.61，42/186 tiles 零检出。

**根因分析 (Step 0-2):**
- GF6 RPN-missed 目标尺寸与 covered 目标几乎相同 → 不是 anchor scale 问题
- 0/676 missed boxes 超过 max anchor 128px → 不是目标太大
- GF6 oversampling (×3 weight) → RPN recall 不变 (0.6952→0.6943) → 不是样本频率问题
- Expanded AR (0.2~5.0) → RPN recall 降至 ~0.666 → 不是 aspect ratio 问题
- 多尺寸推理 (224→448) → RPN recall 从 0.70 跌至 0.16 → 不是输入分辨率问题
- **当前结论: 当前检测特征路径对 GF6 纹理特征不够判别。代码事实显示 PoC-1 RPN/FPN 直接使用 ConvNeXt `pyramid_raw`，未使用 DINO `g_grid` 或 fused `seq`；因此不能在未接入 DINO/fused features 或未做消融前把根因归因到 DINO ViT。**

**已完成实验:**

| Step 2 | GF6 oversampling (×3, 20 epochs) | 0.6943 | 无效 |
| P2-3 | Expanded AR (0.2~5.0, 20 epochs) | ~0.666 | 恶化 |
| — | 多尺寸推理 (224/320/384/448) | 0.70→0.16 | 崩塌 |

## 15. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| **当前检测特征路径对特定传感器纹理不敏感 (🆕 PoC-2a 发现)** | GF6 RPN recall 0.695 vs non-GF6 0.888，final recall 差 0.25+；当前 PoC-1 检测头直接使用 ConvNeXt `pyramid_raw`，不能直接归因到 DINO ViT | Stage 3.5 优先 partial unfreeze ConvNeXt last 1-2 stages / blocks，lr=head×0.01；ViT 解冻仅作为 DINO/fused feature 接入后的独立消融（见 7.5 和 14.2b） |
| round-trip 坐标误差不可控 | GT 不可靠，训练无效 | PoC 先验证，必要时直接从原始 label 构建 |
| 空间泄漏导致评估虚高 | 错误判断模型性能 | 按源图像/区域划分，不随机切 tile |
| 土地覆盖 semantic head 难收敛 | 32类分割困难 | Focal loss 处理类不平衡 |
| LLM 在联合训练中遗忘 CAP | 丢 Stage2 的对话能力 | 监控 + 动态调整混合比例 |
| 海岸线 edge 对小 tile 效果差 | 边缘片段化 | 增大 context / 降低 skeleton 阈值 |
| MoE 路由退化 (expert 0 unused) | 多任务能力下降 | 调高 aux_loss 或单独修复 |
| NPU bfloat16 坐标转换精度损失 | 米级定位误差 | 坐标转换全部用 float32 |
