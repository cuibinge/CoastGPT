# PoC-4: LLM Fallback + 融合 设计文档

> 日期: 2026-06-23
> 状态: 设计定稿
> 前序: PoC-1 (instance) ✅, PoC-2a (GF6 repair) ✅, PoC-2b (semantic) ✅, PoC-3 (edge) ✅

## 设计目标

在三个检测头（养殖区 Instance、土地覆盖 Semantic、海岸线 Edge）均通过 PoC 验证的基础上，实现：

1. **Known class det-only gating** — 已知类别走检测头优先
2. **Unknown class LLM fallback** — 未知类别走 LLM 生成 GeoJSON，经过完整校验管线
3. **分类型去重** — 检测头结果与 LLM fallback 结果按 Polygon/LineString/Point 分类型去重，known 优先

核心原则：**LLM 负责理解 prompt；label_map.json 负责裁决 known/unknown；branch registry 负责分配检测头；validator 负责约束 LLM fallback。**

## §B — Predictor 接口

```python
# Models/fusion_predictors.py

from abc import ABC, abstractmethod
from dataclasses import dataclass
from typing import List, Optional, Dict
import torch

@dataclass
class PredictorOutput:
    """每个 predictor 的统一输出格式"""
    branch: str              # "instance" | "semantic" | "edge" | "llm"
    features: List[dict]     # GeoJSON Feature dicts (WGS84 coords)
    metadata: dict           # {confidence, num_features, timing_ms, ...}
    raw: Optional[dict]      # 原始输出 (用于 debug/可视化)

class BasePredictor(ABC):
    """所有 predictor 的统一接口"""

    @abstractmethod
    def predict(self, image: torch.Tensor, prompt: str,
                georef: dict, classes: List[str]) -> PredictorOutput:
        """对给定图像和类别列表执行推理"""
        ...

    @property
    @abstractmethod
    def branch(self) -> str:
        ...

class InstancePredictor(BasePredictor): ...
class SemanticPredictor(BasePredictor): ...
class EdgePredictor(BasePredictor): ...
class LLMPredictor(BasePredictor): ...   # 仅用于 fallback; parser 是独立逻辑
```

**关键约束:**
- 每个 Predictor 接收 `classes` 参数，只输出这些类别的结果（不做多余推理）
- `features` 是已完成坐标转换的 WGS84 GeoJSON Feature，FusionPipeline 不再做坐标变换
- LLMPredictor 的 `classes` 是 `unknown_classes`，prompt 被改写为仅请求这些类别

## §C — LLM Parser + Gating

```
prompt 文本
    │
    ▼
┌─────────────────────────────────────────────┐
│ Rule Layer (快速路径)                         │
│  - 提取 [DET]/[CAP]/[VQA] 前缀               │
│  - 若 [CAP]/[VQA] → 跳过所有 detection head   │
│  - 若缺前缀 → 默认 [DET]                      │
└──────────────┬──────────────────────────────┘
               │ (仅 [DET])
               ▼
┌─────────────────────────────────────────────┐
│ LLM Parser                                  │
│  prompt → LLM (轻量单轮) → structured JSON    │
│  {                                           │
│    "task_type": "DET",                       │
│    "target_classes": ["海岸线", "红树林"],     │
│    "raw_mentions": [...],                    │
│    "confidence": 0.92                        │
│  }                                           │
│  若 parse 失败 → Rule Layer fallback          │
│  (从 prompt 中关键词匹配 + label_map 裁决)      │
└──────────────┬──────────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────────┐
│ Gating (deterministic, 无 LLM)               │
│                                              │
│  for each class in target_classes:           │
│    matched = label_map.lookup(class)         │
│    if matched:                               │
│      dispatch[matched.branch].append(class)  │
│    else:                                     │
│      unknown_classes.append(class)           │
│                                              │
│  output: dispatch_map = {                    │
│    "known": {"instance": [...],              │
│              "semantic": [...],              │
│              "edge": [...]},                 │
│    "unknown": [...]                          │
│  }                                           │
└─────────────────────────────────────────────┘
```

**实现级约束:**

1. LLM Parser 只输出 `task_type` + `target_classes` + `raw_mentions` + `confidence`。
2. Parser 不判断 known/unknown，不分配 branch。
3. Gating 只信 `label_map.json`，不信 LLM 对类别归属的判断。
4. Rule Layer fallback 使用 `alias/exact/longest/fuzzy` 的保守匹配策略。
5. parse failure 条件和 `confidence` threshold 写进 config。
6. [CAP]/[VQA] 一律跳过 detection heads。
7. [DET] 且 `unknown_classes` 为空时跳过 LLM fallback。
8. [DET] 且 `target_classes` 为空时默认报错或配置化处理，不建议盲跑全部。

## §D — Validator（校验管线）

### Layer 1: 通用 GeoJSON 校验

扩展 `utils/geojson_builder.py::validate_geojson()`，支持 Polygon + LineString + MultiLineString + MultiPolygon + Point。

```
输入: FeatureCollection dict (+ tile_bounds_wgs84)
  ├─ 1. JSON parse          → hard fail if 不是合法 FeatureCollection
  ├─ 2. Schema check        → hard fail if type≠"FeatureCollection" / 缺 "features"
  ├─ 3. Empty output        → valid=True, early return
  ├─ 4. Per-feature geometry → hard fail if geometry.type 非法 / coords 不闭合 / 自交
  ├─ 5. Coordinate range    → hard fail if coords 超出 tile_bounds
  ├─ 6. Auto-repair         → Polygon 未闭合→auto-close, 环方向→orient ccw, 自交→buffer(0)
  └─ 7. Sliver filter       → min_area / min_length / min_points 过滤
```

**适用范围:** 检测头和 LLM fallback 都走 Layer 1。

### Layer 2: LLM Fallback 专项校验

新增 `utils/geojson_validator.py`，仅对 LLM fallback 结果执行。

```
输入: FeatureCollection + unknown_class_whitelist + tile_bounds
  ├─ 8. Class whitelist    → hard fail if LLM 输出中包含 known class
  │                          (LLM 只能输出 unknown_classes 中的类别)
  ├─ 9. Geometry type check → hard fail if 海岸线输出 Polygon / 养殖区输出 LineString
  ├─ 10. Unknown-class      → hard fail if feature 的 class 不在 unknown_classes 中
  │     policy
  └─ 11. Confidence filter  → < min_confidence → reject feature (可配)
```

### 失败处理约定

| 校验项 | 类型 | 失败行为 |
|--------|------|---------|
| JSON parse | hard fail | 丢弃全部 LLM output |
| Schema | hard fail | 丢弃全部 |
| Geometry validity | hard fail | auto-repair 失败后丢弃该 feature |
| Tile bounds | hard fail | 丢弃越界 feature |
| Empty output | ok | 返回空 FeatureCollection |
| Auto-repair | best-effort | 修复失败丢弃该 feature |
| Sliver filter | configurable | 默认过滤 |
| Class whitelist violation | hard fail | 丢弃违规 feature |
| Confidence < threshold | configurable | 默认丢弃 |

### ValidationReport

```python
@dataclass
class ValidationReport:
    passed: bool
    valid_features: List[dict]
    rejected_features: List[dict]   # 含 reject reason
    stats: dict                     # {n_total, n_passed, n_rejected, n_repaired, ...}
```

**重要:** Dedup 不放在 validator 内部，作为 validation 之后的独立步骤。

## §E — Dedup（去重模块）

新增 `utils/geojson_dedup.py`，dispatch-based 纯规则模块。

### Layer 1: LLM 自去重 (within-source)

```
输入: LLM fallback features (均来自 validator 通过的 unknown classes)

按 geometry type 分组:
  Polygon:    projected CRS IoU > threshold_internal → merge (keep higher confidence)
  LineString: buffered IoU > threshold_internal → keep longer/confident
  Point:      distance < threshold → keep higher confidence
```

### Layer 2: Cross-source 去重 (LLM vs Detection)

```
输入: (det_features, llm_deduped_features)

同样按 geometry type 分组:
  Polygon:    projected CRS IoU > threshold_cross → keep det (known 优先)
  LineString: buffered IoU > threshold_cross → keep det
  Point:      distance < threshold → keep det

冲突时 always keep known (detection head)
```

**关键约束:**
- 去重是纯规则模块，不依赖 torch
- 去重只在相同 geometry family 内进行，不比较 Polygon vs LineString 等跨类型对象
- LLM 自去重使用更严格阈值，cross-source 去重使用设计文档阈值
- 重叠阈值写进 config
- 检测头内部去重不在本模块处理（各自 head 后处理负责）

```python
# Geometry family dispatch — 覆盖 Polygon/MultiPolygon, LineString/MultiLineString, Point/MultiPoint
DEDUP_STRATEGIES = {
    "area":  iou_dedup,           # Polygon, MultiPolygon
    "line":  buffer_iou_dedup,    # LineString, MultiLineString
    "point": distance_dedup,      # Point, MultiPoint
}
```

## §F — FusionPipeline 主流程

```python
# Models/fusion_pipeline.py

class FusionPipeline:
    def __init__(self, predictors: Dict[str, BasePredictor], config: FusionConfig):
        self.predictors = predictors  # {"instance": ..., "semantic": ..., "edge": ..., "llm": ...}
        self.label_map = load_label_map()
        self.config = config

    def run(self, image: torch.Tensor, prompt: str, georef: dict) -> dict:
        """主入口: 输入 image + prompt → 输出 FeatureCollection dict"""

        # Step 1: Prefix check (rule layer, fast path)
        task_prefix = self._extract_prefix(prompt)  # [DET] / [CAP] / [VQA]

        # Step 2: [CAP]/[VQA] early return — 纯文本路径，跳过检测头
        if task_prefix in ("CAP", "VQA"):
            return self.predictors["llm_text"].predict(image, prompt, georef)

        # Step 3: LLM Parser → structured extraction
        parse_result = self._parse_prompt(prompt, task_prefix)

        # Step 4: Gating (deterministic)
        dispatch_map = self._gate(parse_result.target_classes)

        # Step 5: Run detection heads (known classes only)
        det_features = []
        for branch, classes in dispatch_map.known.items():
            if classes:
                output = self.predictors[branch].predict(image, prompt, georef, classes)
                validated = self._validate_layer1(output.features, georef)
                det_features.extend(validated)

        # Step 6: LLM Fallback (unknown classes only)
        llm_features = []
        if dispatch_map.unknown:
            llm_prompt = self._build_fallback_prompt(prompt, dispatch_map.unknown)
            output = self.predictors["llm"].predict(image, llm_prompt, georef, dispatch_map.unknown)
            validated = self._validate_layer1(output.features, georef)
            policy_ok = self._validate_layer2(validated, dispatch_map.unknown)
            llm_features = policy_ok

        # Step 7: Dedup
        final_features = self._dedup(det_features, llm_features)

        # Step 8: Build final FeatureCollection
        return build_feature_collection(final_features), diagnostics
```

### 与设计文档 §5.3 的对应关系

| §5.3 step | 说明 | 对应模块 |
|-----------|------|---------|
| 1. parse prompt | task type + target classes | LLM Parser + Rule Layer |
| 2. [CAP]/[VQA] | skip heads | `_extract_prefix()` → early return |
| 3. [DET] known | dispatch to heads | Gating → head predictors |
| 4. coord transform | pixel→WGS84 | 各 Predictor 内部完成 |
| 5. LLM fallback validate | parse+schema+geo+bounds+policy | Validator Layer1 + Layer2 |
| 6. dedup | keep known on conflict | `geojson_dedup.py` |
| 7. final output | FeatureCollection + diagnostics | `build_feature_collection()` |

### LLM fallback 跳过条件

- `[CAP]` / `[VQA]` 前缀 → 整个 detection 分支不触发
- `[DET]` 且 `unknown_classes` 为空 → LLM fallback 不运行
- `[DET]` 且 `target_classes` 为空 → 按 config 策略：报错 / 跑全部 head / LLM 自由生成

## §G — 评估指标

PoC-4 的评估重点不是 mAP/mIoU/F1 提升，而是融合管线本身的正确性。

### G1: Gating Accuracy

| 指标 | 目标 |
|------|------|
| prefix 识别准确率 | > 0.99 |
| LLM Parser `task_type` 准确率 | > 0.90 |
| LLM Parser `target_classes` 召回率 (vs 人工标注) | > 0.85 |
| Rule Layer fallback 触发率 (监控项) | 记录 |

### G2: Fallback Trigger Correctness

| 指标 | 目标 |
|------|------|
| unknown class 正确触发 LLM fallback | > 0.95 |
| known class 错误触发 LLM fallback | < 0.05 |
| unknown_classes 为空时正确跳过 LLM | 1.0 |

### G3: Validator Correctness

| 指标 | 目标 |
|------|------|
| hard fail 正确拒绝无效 feature | > 0.95 |
| auto-repair 成功率 | 监控 |
| Layer2 class whitelist 违规检出 | 1.0 |

### G4: Dedup Correctness

| 指标 | 目标 |
|------|------|
| cross-source 去重后 known 被错误移除 | 0 |
| LLM 自去重后 duplicate 残留率 | < 0.05 |

### G5: Known-Class Non-Regression

在 known-only prompts 上评估：

| 指标 | 目标 |
|------|------|
| Instance head F1 vs PoC-1 baseline | ΔF1 > -0.02 |
| Semantic head mIoU vs PoC-2b baseline | ΔmIoU > -0.02 |
| Edge head F1@3px vs PoC-3 baseline | ΔF1 > -0.02 |

### G6: Final GeoJSON Validity

| 指标 | 目标 |
|------|------|
| JSON parse success rate | 1.0 |
| Schema valid rate | 1.0 |
| Geometry valid rate (all types) | > 0.95 |
| Coordinate-in-tile rate | 1.0 |

### 评估样本集

- **mixed set (~100 samples):** 覆盖三种检测头 + 至少 5 个 unknown class 样本
- **prompt fixtures:** known/unknown 边界样本（known class 用别名提问、含混表述如 "所有的养殖设施"）
- **validator fixtures:** 故意构造无效 GeoJSON / 越界坐标 / known class 泄漏
- **dedup fixtures:** 构造重叠 feature 对 (det + LLM)
- 故意包含一个 unknown class 的 DET prompt

## §H — 通过标准

PoC-4 通过 = 以下 5 条全部满足：

1. **管线闭环** — 100 个 mixed set 样本跑通，无 crash，输出合法 FeatureCollection
2. **Gating 正确** — `task_type` 准确率 ≥ 0.90，prefix 识别 ≥ 0.99
3. **Known 不退化** — 在 known-only prompts 上，三种检测头指标相对 PoC-1/2b/3 baseline 下降 ≤ 0.02
4. **Validator 有效** — class whitelist 违规检出 100%，hard fail 正确拒绝 ≥ 0.95
5. **Dedup 正确** — cross-source 冲突时 zero known-mistakenly-removed

**不阻塞但需记录:**
- LLM Parser 延迟 (ms per prompt)
- LLM Fallback 生成质量（人工抽查 ~20 个 unknown class 输出的合理性）
- Rule Layer fallback 触发率

## 附录：Checkpoint 加载策略

PoC-4 采用**分别加载、运行时组合**：

- 脚本接受多个 checkpoint 路径 (`--inst-ckpt`, `--sem-ckpt`, `--edge-ckpt`, `--llm-ckpt`)
- 用 manifest 管理路径和版本
- 每个分支封装成独立 predictor
- FusionPipeline 只做 routing、fallback、validation、dedup 和输出

PoC-5 联合训练产出统一 checkpoint 后，只需新增一个 JointPredictor 或替换 manifest 中的加载项，不改变 FusionPipeline 的外部接口。
