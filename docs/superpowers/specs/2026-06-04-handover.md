## 二、未解决 — 非 224 分辨率训练报错

### 2.1 错误现象

在 128 和 512 分辨率下，Mask R-CNN forward 在 `decode()` 时崩溃：

```
RuntimeError: shape '[2752, -1]' is invalid for input of size 10752
```

- `2752` = 128 分辨率下 anchor generator 计算的总 anchor 数
- `10752` = RPN 预测器实际输出的 bbox delta 元素数
- `10752 / 2752 = 3.909 ≠ 4` — anchor grid 与实际特征图尺寸不匹配

512 分辨率同理：`44032` vs `172032`（同样比例不匹配）。

### 2.2 已排除的原因

| 尝试 | 结果 |
|------|------|
| 改 anchor 结构 (2-2-2 → 2-2-3) | 仍然崩 |
| 改 ViT 整除尺寸 (112/504) | 仍然崩，box_sum 值不变 |
| 改 dataset image_size | 仍然崩 |
| smoke test 硬编码 224 → 已修 | smoke test 过了，训练 loop 仍崩 |
| min_size/max_size 匹配 image_size | 仍然崩 |

### 2.3 根因推测

`GeneralizedRCNNTransform` 内部有 `size_divisible=32` padding 逻辑，在非 224 分辨率下改变了实际图像尺寸，导致 FPN 输出的特征图大小与 anchor grid 不匹配。torchvision 0.15（PyTorch 2.1）的 `GeneralizedRCNNTransform` 对非标准分辨率处理可能有 bug 或需要额外参数。

### 2.4 建议排查方向

1. 在 `GeneralizedRCNNTransform.forward()` 中添加 print，确认最终的 `image_sizes` 和 FPN 输出尺寸
2. 检查是否有 `fixed_size` 参数可用（torchvision ≥ 0.16）
3. 或者：坚持用 224 训练，不考虑原生分辨率——把"分辨率影响"的验证推到 multi-scale 阶段
