# 实验部分执行清单

> 适用对象：Task-aware Heterogeneous Expert Routing / Prompt-aware Heterogeneous MoE Routing 论文实验部分  
> 核心目标：验证异构专家路由、Dense-to-Language Evidence Bridge、Geometry-safe GeoJSON Generation 三个创新点是否有效。  
> 使用方式：按“数据准备 → Baseline → 主实验 → 消融 → 分析 → 可视化 → 写作材料归档”的顺序执行。

---

## 0. 实验总目标

本实验部分需要回答以下问题：

- [ ] 异构专家路由是否优于 LLM-only、Dense-only、Fixed Routing、Softmax Routing？
- [ ] 多标签 sigmoid 路由是否优于单标签 softmax 路由？
- [ ] Dense-to-Language Evidence Bridge 是否提升解释、报告和属性生成的可信度？
- [ ] Geometry-safe GeoJSON Generation 是否比 LLM 直接生成坐标更稳定、更合法、更准确？
- [ ] loc_tokens 直接生成坐标是否不适合复杂 polygon / GeoJSON geometry？
- [ ] 模型是否能在文本生成、实例分割、语义分割、边界提取和 GeoJSON 输出之间实现统一建模？

- [ ] LLaVA-style baseline

- [ ] RS-LLaVA-style baseline，可选

- [ ] 原始 MoEProjection + LLM，不接 dense branch

---

### 3.3 内部架构变体

这是最重要的 baseline 组。

- [ ] B1: LLM-only  
  所有任务都走 LLM，坐标通过 loc_tokens 或文本直接生成。

- [ ] B2: Dense-only  
  只做分割 / 边界 / GeoJSON，不做解释和文本生成。

- [ ] B3: Fixed Routing  
  人工根据任务类型固定分支，不使用 Prompt-aware Gate。

- [ ] B4: Softmax Single-route Gate  
  每个样本只能选择一个分支。

- [ ] B5: Homogeneous MoEProjection  
  只在 LLM projection 内做 MoE，不包含 FPN dense experts。

- [ ] B6: Ours without Evidence Bridge  
  LLM 不接收 dense evidence，只根据图像和 prompt 解释。

- [ ] B7: Ours without Geometry-safe Serializer  
  LLM 直接生成 GeoJSON 坐标。

- [ ] B8: Ours full model  
  完整方法。

## 13. 实验结论应该支撑的核心表述

最终实验需要支持以下结论：

- [ ] 本方法能够在一个统一框架下完成文本生成、空间分割、边界提取和 GeoJSON 构建。
- [ ] 多标签异构路由比单标签路由更适合混合型地理空间任务。
- [ ] Dense branch 保留了二维空间结构，因此比 LLM 直接生成坐标更适合高精度几何输出。
- [ ] Dense-to-Language Evidence Bridge 能显著减少解释幻觉，提高解释与分割结果的一致性。
- [ ] Geometry-safe GeoJSON Generation 能提高 GeoJSON 合法率、polygon 有效性和坐标一致性。
- [ ] loc_tokens 更适合点 / bbox / 粗粒度坐标，不适合作为复杂 polygon 生成的主路径。
- [ ] Prompt-aware Gate 能根据任务类型和目标地物动态激活合理分支。
